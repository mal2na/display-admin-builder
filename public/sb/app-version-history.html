APP 버전 관리 — 변경/승인 이력

승인대기는 동시에 여러 건 존재할 수 있으므로 승인 요청 취소는 행별 액션으로 두되, 날짜 컬럼과 섞지 않고 맨 오른쪽 관리 컬럼으로 분리합니다. 사유는 행 펼침과 모달 두 방식을 아래 화면에서 직접 전환해 비교할 수 있습니다.

개정 요지

세 가지를 바꿨습니다

취소 버튼 — 날짜 컬럼에서 관리 컬럼으로

현행

승인 요청 취소 컬럼 하나에 처리 일시와 버튼이 함께 들어감

개정

행별 액션은 유지. 맨 오른쪽 관리 컬럼으로 분리하고, 승인대기 행에만 노출

왜: 한 컬럼에는 한 종류의 값만 들어가야 헤더가 의미를 갖습니다. 날짜와 버튼이 섞이면 승인 요청 취소가 취소 일시인지 취소 버튼인지 헤더만 봐서는 알 수 없고, 엑셀 항목 정의로 옮길 때도 깨집니다. 액션은 관례대로 맨 오른쪽 고정이 스캔에도 유리합니다.

사유 — 버튼 대신 텍스트를 노출

현행

셀에 취소 사유 / 반려 사유 버튼만. 표에서는 내용을 전혀 알 수 없음

개정

사유 텍스트를 2줄로 노출. 클릭하면 전문 — 펼침 또는 모달(선택)

왜: 모달 자체가 문제가 아니라 셀에 버튼만 있는 것이 문제입니다. 첫 두 줄만 보여도 “무슨 사유인지”는 대부분 판별되고, 사유가 목록 데이터로 잡히니 엑셀 다운로드에서도 빠지지 않습니다.

컬럼 정리 — 한 컬럼 = 한 의미

현행

처리일시와 승인 요청 취소가 같은 값을 두 번 표시. 사유 컬럼명이 취소/반려로 이중

개정

처리일시 하나로 통합, 컬럼명은 사유. 취소인지 반려인지는 상태 뱃지가 이미 말해줌

왜: 같은 정보를 두 열에 두면 어느 쪽이 정답인지 운영자가 매번 되묻게 됩니다. 셀 안에 반려 사유/취소 사유 라벨을 작게 달아 두면 컬럼명은 사유 하나로 충분합니다.

검토

사유 전문, 모달로 해도 되나

결론부터 — 됩니다. 다만 “버튼만 두는 현행”은 어느 쪽으로 가든 바꿔야 합니다. 셀에 2줄 인라인을 남기는 것을 전제로 두 방식을 비교했습니다.

기준 현행 · 버튼 → 모달 A · 인라인 → 행 펼침 B · 인라인 → 모달
표에서 사유 파악 ✕버튼만 보임열어야 알 수 있음 ○2줄 노출 ○2줄 노출
여러 건 동시 비교 ✕불가 ○여러 행 동시 펼침반려 패턴 분석에 유리 △한 번에 1건2줄 요약으로는 비교 가능
전문 가독 폭 ○넓음 ○행 전체 폭 사용 ○넓음 · 스크롤 자유
첨부·서식 확장 ○ △패널이 길어지면 표가 무너짐 ○캡처·링크·이전 반려 이력까지 수용
표 리듬 유지 ○ ✕펼칠 때마다 행 위치가 밀림 ○표는 그대로

구현·QA 비용 ○낮음 △행 상태 관리 추가 ○낮음 · 기존 모달 재사용

결론 — 모달(B)로 가도 좋습니다

제가 처음에 모달을 반대한 근거는 “사유를 표에서 전혀 볼 수 없다”였는데, 그건 모달의 문제가 아니라 버튼의 문제였습니다. 셀에 2줄만 남겨 두면 모달의 단점은 대부분 사라지고, 표 리듬·정렬·첨부 확장에서는 오히려 모달이 낫습니다.

  • 다만 조건 하나 — 트리거는 버튼이 아니라 사유 텍스트 자체여야 합니다. 버튼을 다시 두면 컬럼 폭을 버튼이 먹고 원점으로 돌아갑니다.
  • 행 펼침(A)이 유리한 경우 — 반려 사유의 패턴을 모아 보는 업무가 실제로 있다면. 여러 건을 동시에 펼쳐 비교할 수 있는 건 A뿐입니다.
  • 반려 사유에 캡처·링크·이전 반려 이력을 붙일 계획이 있다면 망설임 없이 B입니다.
개정안 화면

두 방식을 직접 눌러 보세요

실제로 동작합니다. 사유 셀을 클릭하면 선택한 방식대로 열리고, 승인대기 행의 취소를 누르면 사유 입력 모달을 거쳐 그 행이 요청취소로 바뀝니다.

액션과 사유의 규칙

관리 컬럼
승인대기 행에만 취소가 노출되고, 나머지 상태는 -. 승인대기가 여러 건이면 각 행에서 개별 취소할 수 있습니다.
취소 권한
요청자 본인만 실행 가능. 타인의 요청 행은 버튼이 비활성으로 보이고 사유가 툴팁으로 안내됩니다 — 아래 표에서 김지훈 요청 건이 그 예입니다.
승인반려
사유 필수. 작성자는 승인 담당자. 사유 없이는 반려 처리 불가.
요청취소
사유 필수(10자 이상). 작성자는 요청자 본인. 취소 후 되돌릴 수 없고, 재요청은 새 승인 ID로 생성됩니다.
모달 사용
사유 입력은 언제나 모달(되돌릴 수 없는 실행의 확인). 사유 열람은 A/B 중 택일 — 어느 쪽이든 셀의 2줄 인라인은 유지합니다.
