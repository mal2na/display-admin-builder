1. 개요

가. 범위

• 본 정책서는 전시 어드민에서 전시 구조, 메뉴, 컨테이너, 템플릿, 컴포넌트, 배너, 퀵메뉴, 개인화 영역을 관리하는 기준을 정의한다.

• 포함 범위는 노출 조건 설정, 랜딩·복귀 연결, 검수·승인·게시·롤백, 채널 노출 상태 확인, 성과 측정이다.

• 주문, 가입, 납부, 상담, 혜택 사용 같은 후속 업무 처리는 본 정책서의 범위에서 제외한다.

• BSS와 CVM이 제공하는 판매 상태, 고객 상태, 보유 상품, 혜택 기간, 오퍼 조건은 전시 가능 여부와 우선순위 판정에 사용한다.

나. 설계 원칙

1. 전시 구조 중심 관리
전시 어드민은 화면 구성 단위와 노출 조건을 기준으로 관리한다.
NC 전시는 Container, Template, Corner, Component 단위로 표준화한다. 화면 구조, 노출 조건, 게시 상태, 변경 이력은 같은 단위 기준으로 관리한다.

2. 모듈형 전시 구조
전시 요소는 최소 단위로 모듈화한다.
전시 구조는 Atom → Component → Corner → Template → Container 계층으로 관리한다. 운영자는 화면을 새로 만드는 것이 아니라 표준화된 구성 단위를 조합해 화면을 구성한다.

3. 개인화 요소 근거 표시
개인화 요소에는 노출 근거를 함께 관리한다.
개인화 Component, Corner, Template, Container에는 적용 근거와 제한 사유를 남긴다.

3-1. 여정·의도 기반 전시
전시는 고객 여정, 세그먼트, 현재 의도, 필요 정보, 관계 맥락을 참조할 수 있다.
다만 전시 어드민은 고객 맥락을 직접 해석하지 않고, 승인된 연계 시스템의 판정값과 운영자가 정의한 조건 그룹을 기준으로 전시 후보와 우선순위를 관리한다.

4. 개인화 제한 기준 관리
개인화 제한이 필요한 전시는 제한 기준과 예외 기준을 함께 관리한다.
숨김, 관심없음, 일정 기간 비노출, 필수 고지 예외는 전시 조건과 이력 기준으로 남긴다.

5. 통제된 운영
전시 변경은 통제된 운영 절차를 따른다.
전시 변경은 작성, 검수, 승인, 예약, 게시, 중지, 롤백 상태를 거친다.

6. 배너 통합 관리
배너는 기간형 전시 Component이면서 별도 통합 관리 대상이다.
동일 배너가 여러 화면과 Container에 배치될 수 있으므로 배너 캠페인·소재·노출 상태를 별도 메뉴에서 통합 관리한다.

7. 안전한 자동화와 성과 기반 개선
AI는 후보를 제안하고, 운영자가 확정한다.
AI 후보는 운영자 승인 전 채널에 노출하지 않는다. 자동 적용 범위와 조건은 사전에 정의한다.
전시 성과는 노출수, 클릭수, CTR(클릭률), 후속 행동, 숨김, 이탈, 실험 결과로 판단한다. 이상이 있으면 중지하거나 롤백한다.

3. 기본 개념

1) 정책 목적

NC 전시관리는 T월드, T다이렉트, T멤버십, T우주의 분리된 전시 구조를 하나의 기준으로 통합한다.

채널별로 흩어진 메뉴, 컨테이너, 템플릿, 컴포넌트, 배너, 콘텐츠는 공통 전시 단위로 정리한다. 중복 요소는 줄이고, 채널별 예외는 필요한 경우에만 둔다.

2) 전시 구성 요소

NC 전시는 모듈형 전시 구조를 기준으로 한다. 운영자는 표준 단위로 화면을 구성하고, 고객 상태와 화면 목적에 따라 적용 구조를 확인한다.

전시 구조는 Atom → Component → Corner → Template → Container 순서로 구성한다.

화면 구성과 노출 조건은 서버에서 관리한다. 채널은 승인된 전시 데이터를 해석해 화면에 표시한다.

Container는 화면 단위이고, Template은 Container 안에서 적용되는 화면 구성안이다. Corner는 화면 영역, Component는 전시 모듈, Atom은 문구·이미지·CTA 같은 최소 표시 요소다.

Container는 기본 Template을 가진다. 고객 상태나 로그인 여부에 따라 여러 Template으로 분기할 수 있다.

Template은 조건값과 전시 기간을 가진다. 캠페인, 기획전, 시즌성 혜택처럼 한시적으로 다른 화면을 보여줄 때 기간형 Template을 사용한다.

필수값, 승인 상태, 게시 차단, 복귀 기준은 정책 상세에서 정의한다.

Corner하나 이상의 Component를 묶어 화면의 특정 영역을 구성하는 단위다.Corner 안에서 Component 순서와 대체 후보를 추천할 수 있다.

Container채널에 반영되는 화면 또는 영역 단위이며, 적용 가능한 Template 목록을 가진다.사용처와 성과 기반 개선 후보를 제안할 수 있으나 Container 생성·수정·상태 변경은 운영자가 확정한다.

• Atom

Atom은 전시를 구성하는 가장 작은 재사용 단위다.

텍스트, 버튼, 이미지, 아이콘, 배지, 가격, 혜택 문구, CTA 같은 요소가 Atom에 해당한다. Atom은 단독으로 화면을 구성하지 않고, Component를 구성하는 재료로 사용한다.

구분설명예시

버튼 Atom고객 행동을 유도하는 단위조회하기, 변경하기, 신청하기
이미지 Atom시각 요소 단위배너 이미지, 상품 이미지, 아이콘

Atom의 사용 가능 유형과 속성은 디자인 라이브러리 기준을 따른다. 사용 목적, 타겟 세그먼트, 베리에이션 생성 기준 같은 세부 운영 기준은 기능 정의와 정책 상세에서 다룬다.

• Component

Component는 여러 Atom을 조합한 전시 모듈이다.

고객에게 하나의 의미 있는 정보나 행동을 제공하는 단위이며, 카드, 배너, 리스트, 퀵메뉴, 요약 정보, 추천 혜택 등이 Component에 해당한다. Component는 사전에 정의된 유형과 속성 기준 안에서 사용하며, 노출 조건에 따라 구성 데이터가 달라질 수 있다.

아래 Component 유형은 정책 정리를 위한 예시이며, 실제 유형명과 속성은 상세 설계에서 확정한다.

• Corner

Corner는 하나 이상의 Component를 묶어 화면의 특정 영역을 구성하는 단위다.

예를 들어 메인화면의 “이용 요약”, “추천 혜택”, “빠른 실행”, “공지/배너” 같은 영역이 Corner에 해당한다.

• Template

Template은 여러 Corner를 배치한 표준 화면 구조다.

Template은 화면의 골격이며, 고객 상태나 채널 조건에 따라 다른 Template을 사용할 수 있다.

구분설명

Template의 레이아웃 선택, 분기 조건, 기본 Template, 기간, 우선순위, 이력 기준은 기능 정의와 정책 상세에서 다룬다.

• Container

Container는 메인화면, 추천, 기획전 리스트, 이벤트 리스트처럼 채널에 반영되는 전시 화면 또는 영역 단위를 의미한다.

예를 들어 메인 전시 화면을 생성하려면 “메인” Container를 신규 등록해야 한다. 하나의 Container에는 조건 옵션에 따라 복수의 Template이 등록될 수 있으며, 고객 상태와 노출 조건에 따라 실제 반영되는 Component와 순서가 달라질 수 있다.

구분설명
Container 역할전시 화면 또는 영역 단위와 해당 화면에 적용할 Template 목록을 관리한다.
관계Container와 화면은 1:1 관계이며, Container와 Template은 1:N 관계를 가질 수 있다.
기본 구성Container는 기본 화면 구성을 나타내는 Template을 기준 구조로 가진다.
반영 기준Container + Template + 고객 상태 + 노출 조건
고객 상태 예시: 로그인 여부, 고객 유형, 보유 상품, 멤버십 등급, 최근 행동, 진행 중 업무
노출 조건 예시: 채널, 앱·웹, OS, 앱 버전, 노출 기간, 권한, 세그먼트, 우선순위, 제외 조건
예시메인화면, 추천, 기획전 리스트, 이벤트 리스트, 혜택 영역

Container는 채널에서 호출하는 화면·영역 단위 ID이므로 삭제하지 않고 상태값으로 관리한다. Container 자체의 순서는 관리 대상이 아니며, 노출 순서와 배치는 Template, Corner, Component 또는 배너 배치 기준에서 관리한다.

전시 어드민은 Container와 Template의 관계, 적용 조건, 채널 노출 상태를 관리한다.

전시 카테고리의 Depth, 명칭, 상품·태그 매핑 기준은 목록 정책서에서 정의하며, 전시관리는 목록 정책서에서 정의한 카테고리를 노출 조건과 화면 구성 기준으로 참조한다.

1) 전시 범위·경계 정책 (PG-DSP-SCP-001)

• 전시 관리 대상 (PI-DSP-SCP-001)
- 전시 어드민의 직접 관리 대상은 화면 구조, 탐색·분류, 캠페인·소재, 실행 연결, 운영 조건·상태로 구분한다.
- 화면 구조 관리 대상은 Container, Template, Corner, Component, Atom이며, 화면 골격·영역·모듈·표시 요소의 구성 기준을 관리한다.
- 탐색·분류 관리 대상은 메뉴, 전시 카테고리이며, 고객이 전시 영역에 진입하고 화면·영역을 구분하는 구조를 관리한다.
- 캠페인·소재 관리 대상은 배너 캠페인과 배너 유형·소재이며, 동일 배너의 화면별 배치와 일괄 제어 범위를 관리한다.
- 실행 연결 관리 대상은 랜딩 연결값이며, CTA, URL, 딥링크, 복귀 맥락처럼 전시에서 업무 화면으로 진입시키는 연결 정보를 관리한다.
- 운영 조건·상태 관리 대상은 노출 조건, 우선순위, 게시 상태, 승인 상태이며, 전시가 언제 누구에게 어떤 상태로 노출되는지를 관리한다.
- 전시 카테고리는 화면·영역 분류, 노출 위치, 정렬 기준처럼 전시 구조를 구성하는 범위에서 관리하며, 상품 카테고리 체계와 상품·태그 매핑의 상세 기준은 목록 정책서에서 관리한다.
- 주문, 가입, 납부, 상담, 혜택 사용의 업무 처리 로직은 전시 대상이 아니며, 전시는 해당 업무로 진입시키는 구조·조건·상태만 관리한다.
• 공통·채널 특화 구분 (PI-DSP-SCP-002)
- 2개 이상 채널에서 동일 목적과 동일 속성으로 사용할 수 있는 전시 요소는 공통 표준 단위로 등록한다.
- 채널 특화 요소는 채널 고유 규격, 외부 제휴, 법적 표기, 운영 권한이 달라 공통화할 수 없는 경우에만 허용하며 예외 사유와 적용 채널을 필수 등록한다.
• 중복 등록 차단 (PI-DSP-SCP-003)
- 동일 채널, 동일 화면 용도, 동일 노출 위치, 동일 기간에 목적이 같은 Container 또는 배너 캠페인을 중복 등록할 수 없다.
- 중복 가능성이 감지되면 기존 전시 ID, 사용처, 게시 상태를 표시하고 신규 등록 대신 수정·복제·기간 교체 중 하나를 선택하게 한다.

2) 컨테이너·템플릿 운영 정책 (PG-DSP-PGE-001)

• Container 필수값 (PI-DSP-PGE-001)
- Container는 메인화면, 메뉴, 기획전, 혜택 영역처럼 운영자가 관리해야 하는 화면 또는 영역 단위로 생성한다.
- Container 생성 시 Container명, 화면·영역 용도, 적용 채널, 담당 조직, 담당자, 기본 Template, 공개 상태, 승인 상태를 필수값으로 둔다. 상위 화면이나 메뉴에 연결되는 Container는 화면 계층과 메뉴 연결 위치를 함께 등록한다.
- 하나의 Container에는 조건 설정 유무에 따라 필요한 기본 Template을 반드시 등록해야 하며, 기본 Template이 없으면 검수 요청과 게시를 차단한다.
- 동일 목적, 동일 채널, 동일 화면 계층·메뉴 연결 위치의 Container는 중복 생성할 수 없으며, 기존 Container를 수정하거나 Template을 추가해 관리한다.
• Container 상태 관리 (PI-DSP-PGE-001-1)
- Container는 채널에서 호출하는 화면·영역 단위 ID이므로 삭제하지 않고 공개 상태, 전시 여부, 사용 상태로 노출을 제어한다.
- 운영 중인 Container를 노출 대상에서 제외할 때는 삭제가 아니라 미전시 또는 사용중지 상태로 전환하고, 연결된 메뉴, Template, Corner, 배너, CTA, 퀵메뉴 사용처를 먼저 확인한다.
- Container 자체에는 전역 순서를 두지 않는다. 화면 안의 노출 순서는 Template의 Corner 배치, Corner 안의 Component 순서, 배너 Slot 순서, 메뉴 연결 순서 중 해당 전시 단위의 정책을 따른다.
- Container ID를 타 채널이나 외부 시스템에서 호출 중인 경우 상태 변경 전 영향 범위와 롤백 대상을 확인하고 변경 이력을 남긴다.
• Corner 유형 매핑 기준 (PI-DSP-PGE-001-2)
- Corner 유형은 Corner가 Container 또는 Template에 매핑되는 시점의 기준을 따른다.
- 매핑 후에는 Corner 유형 관리에서 유형 정보를 임의로 변경하지 않는다.
- 매핑된 Corner 유형을 변경해야 하는 경우 연결된 Container, Template, Component, 배너, 랜딩, 노출 조건의 영향 범위를 확인하고 재검수 대상으로 본다.
- Corner 유형별 사용 여부가 미사용이면 해당 유형은 신규 Corner 선택 대상에서 제외한다.
• 조건 속성 판정 (PI-DSP-PGE-002)
- 조건 속성 N은 모든 대상에게 동일 Template을 적용하는 Container이며 기본 Template 1개를 필수 등록한다.
- 조건 속성 Y는 로그인 여부, 보유 상품 여부, 멤버십 등급, 세그먼트, 채널, OS, 앱 버전, 권한, 오퍼 대상 여부 중 하나 이상으로 Template을 분기하는 Container다.
- 조건 속성 Y에서는 운영자가 정의한 조건 그룹별 Template을 각각 등록한다. 예를 들어 T4S 화면은 비로그인, 로그인(이용·보유 조건 충족), 로그인(이용·보유 조건 미충족)처럼 고객 상태와 상품·혜택 관계에 따라 Template을 분기할 수 있다.
- 어느 조건 그룹에도 해당하지 않는 경우 적용할 기본 Template을 필수 등록한다.
- 조건 판정 실패, 조건 미충족, CVM 등 원천 데이터 미회신 시에는 개인화·조건형 Template을 확정하지 않고 기본 Template 또는 사전에 지정한 대체 Template으로 대체한다.
• 기본 Template 기준 (PI-DSP-PGE-002-1)
- 기본 Template은 조건에 맞는 Template이 없을 때 화면 공백을 막기 위한 대체 화면 구성이다.
- 전시 중인 기본 Template은 Container별로 1개만 허용한다.
- 로그인, 비로그인처럼 조건 그룹이 나뉘는 경우에도 각 조건 그룹에서 적용할 기본 Template을 명확히 지정한다.
- 새 기본 Template이 승인되면 기존 기본 Template은 새 기본 Template 승인 완료 시점까지만 유효하도록 종료일시를 조정한다.
• Template 교체·복귀 (PI-DSP-PGE-003)
- 동일 Container와 동일 조건 그룹에 기간형 Template을 추가할 때 시작일시, 종료일시, 교체 대상 Template, 종료 후 복귀 Template을 필수 입력한다.
- 로그인, 비로그인 등 같은 조건 그룹 안에서는 같은 기간에 전시 중이거나 전시 예정인 Template을 중복 등록할 수 없다.
- 조건 그룹이 새로 추가되는 경우에는 적용 범위, 기본 Template, 중복 판정 기준을 먼저 정해야 한다.
- 승인된 기간형 Template은 시작일시에 맞춰 기존 Template을 대체한다.
- 종료 시각이 지나면 기본 Template 또는 지정된 복귀 Template으로 전환하고 종료 이력을 저장한다.
- 복귀 Template이 없거나 사용할 수 없는 상태이면 게시를 차단한다.
• 미승인 반영 차단 (PI-DSP-PGE-004)
- Draft, Review, Rejected 상태의 Container·Template은 채널 반영, 예약 게시, 캐시 갱신 요청을 할 수 없다.
- 승인 완료 전에는 신규 또는 수정 Template을 채널에 반영하지 않는다.
- 미승인 상태에서는 기존 승인 Template 또는 기본 Template을 유지한다.
- 승인되지 않은 조건 분기나 기간형 Template이 포함되면 해당 분기는 사용하지 않고 기본 Template 또는 기존 승인 Template으로 대체한다.
- 승인 완료 시점에는 조건 그룹, 전시기간, 기본 Template 중복 여부를 다시 확인한다.

3) 1Depth 화면 전시 기준 정책 (PG-DSP-HOM-001)

• 1Depth 화면 구성 기준 (PI-DSP-HOM-001)
- 1Depth 화면은 혜택, Shop, MY처럼 NC채널 대상 서비스의 공통 기능을 고객 여정 기준으로 구분해 전시하는 화면 Container다.
- 각 1Depth 화면 Container에는 화면 용도에 맞는 필수 공지·장애 안내, 진행 중 업무, 상태 요약, 혜택·오퍼, 추천 콘텐츠 Corner를 등록한다.
- 필수 공지·장애 안내는 모든 추천·캠페인보다 우선하며, 기간과 종료 조건이 없으면 게시할 수 없다.
• 홈 화면 지정·변경 기준 (PI-DSP-HOM-002)
- 기본 홈은 승인 완료 상태의 1Depth Container 중에서 지정한다.
- 홈 제공 방식은 고정 홈과 개인화 홈으로 구분한다.
- 개인화 홈은 로그인 여부, 고객 상태, 최근 행동, 보유 상품, 혜택 조건을 기준으로 적용한다.
- 조건 판정에 실패하면 고정 홈 또는 기본 홈으로 대체한다.
- 홈 화면 변경 시 변경 사유, 적용 채널, 적용 시작일시, 기존 홈, 변경 후 홈, 롤백 대상을 저장한다.
- 홈 화면 변경은 검수·승인 완료 후 반영한다. 미승인 상태에서는 기존 홈 화면을 유지한다.
• 빈 상태 처리 (PI-DSP-HOM-003)
- 상태 요약, 혜택, 추천 Corner는 표시 데이터가 없을 때 대체 Component 또는 미노출 중 하나를 사전에 지정해야 한다.
- 빈 상태 처리 방식이 지정되지 않은 Corner는 검수 요청을 차단한다.

4) 메뉴 운영 정책 (PG-DSP-MNU-001)

• 메뉴 노출·연결 운영 기준 (PI-DSP-MNU-001)
- 전시 어드민에서 관리하는 메뉴는 전체 메뉴, 탭메뉴, 퀵메뉴로 구분한다. 전체 메뉴와 탭메뉴는 메뉴 운영 정책에서 관리하고, 퀵메뉴는 퀵메뉴·바로가기 정책에서 별도 관리한다.
- 전체 메뉴는 채널의 1Depth, 2Depth, 3Depth 탐색 구조에 노출되는 메뉴이며, 전시 어드민은 메뉴의 사용 여부, 정렬 순서, 연결 Container 또는 랜딩, 노출 조건, 운영 상태를 관리한다.
- 탭메뉴는 특정 Container 또는 Template 안에서 하위 Corner, Component 묶음, 또는 관련 Container를 전환하는 메뉴성 전시 요소이며, 탭명, 정렬 순서, 기본 선택값, 연결 대상, 노출 조건을 관리한다.
- 핵심 여정으로 이동하는 1Depth 탭과 주요 탭메뉴는 고객 목적과 진입 의도 기준으로 구성하며, 명칭은 고객이 업무 목적을 바로 이해할 수 있는 표현을 사용한다.
- 신규 메뉴 노출은 Container를 신규 생성하거나 기존 Container를 연결한 뒤 메뉴 사용 여부를 설정하는 방식으로 처리하며, 별도의 메뉴 생성·삭제 기능으로 관리하지 않는다.
- 전체 메뉴의 Depth와 상위 메뉴는 채널 구조 기준값으로 조회하며, 전시 어드민에서는 직접 변경하지 않는다. 탭메뉴는 해당 Container 또는 Template 안에서만 정렬·노출을 조정한다.
- 표시 정보는 메뉴명, 탭명, 아이콘, 표시 문구, 노출 채널로 구분한다. 메뉴명, 탭명, 아이콘의 변경은 채널별 적용 가능 범위를 확인한 뒤 반영한다.
- 노출 조건 필수값은 로그인 여부, 권한 조건, 대상 고객군, 채널 조건이다.
- 운영 상태와 소유 정보 필수값은 사용 여부, 공개 상태, 담당 조직, 담당자, 변경 사유다.
- 운영 중인 메뉴나 탭메뉴를 노출 대상에서 제외할 때는 미사용 상태로 전환한다. 연결된 Container, 배너, CTA, 퀵메뉴 사용처가 있으면 영향 범위를 먼저 확인한다.
• 메뉴 연결값 검증 (PI-DSP-MNU-002)
- 전체 메뉴의 연결 대상은 승인된 Container, 내부 랜딩, 외부 랜딩 중 하나여야 하며, 연결값이 없거나 미승인 대상이면 게시할 수 없다.
- 탭메뉴의 연결 대상은 동일 Container 안의 Corner, Component 묶음, 또는 승인된 관련 Container 중 하나여야 하며, 탭을 선택했을 때 노출될 대상이 없으면 게시할 수 없다.
- 전체 메뉴와 탭메뉴는 표시명, 연결 대상, 권한 조건, 노출 채널이 서로 불일치하면 검수 요청을 차단한다.
- 메뉴 또는 탭메뉴 변경 시 기존 유입 경로, 사용처, 채널 영향 범위, 롤백 대상을 확인하고 변경 사유를 저장한다.
• 승인 전 메뉴 반영 제한 (PI-DSP-MNU-003)
- Draft, Review, Rejected 상태의 메뉴 변경은 채널 메뉴 구조, 검색 노출, 캐시 갱신 대상에 반영하지 않는다.
- 승인 완료 전에는 기존 승인 메뉴 구조를 유지하고, 미승인 메뉴는 미리보기에서만 확인할 수 있다.

5) 퀵메뉴·바로가기 정책 (PG-DSP-QCK-001)

• 관리 범위 기준 (PI-DSP-QCK-001)
- 전시 어드민은 퀵메뉴의 후보, 노출 조건, 기본 노출 목록, 추천 순서, 고객 고정·숨김 상태, 실행 불가 시 표시 방식을 관리한다.
- 퀵메뉴가 연결하는 업무의 처리 로직, 신청·변경·납부·상담 완료 기준, 업무별 권한 판정 상세는 각 업무 시스템 또는 업무 정책서에서 관리한다.
- 퀵메뉴는 독립 화면이 아니라 고객을 업무로 진입시키는 전시 Component로 보며, 연결 대상과 노출 조건이 승인된 항목만 사용할 수 있다.
- 퀵메뉴 후보는 고객이 즉시 처리할 수 있는 Micro Task 단위로 관리하며, 단순 홍보성 이동은 퀵메뉴 기본 후보로 등록하지 않는다.
• 후보 등록 기준 (PI-DSP-QCK-002)
- 퀵메뉴 후보는 업무 목적, 표시명, 아이콘, 설명 문구, 랜딩 연결값, 노출 가능 채널, 로그인 필요 여부, 권한 조건, 담당 조직을 모두 가진 항목만 등록한다.
- 연결 대상은 승인된 Container, 내부 랜딩, 외부 랜딩, CTA 중 하나여야 하며, 연결값이 없거나 미승인 상태이면 기본 노출과 추천 후보에서 제외한다.
- 동일 업무 목적과 동일 랜딩을 가진 후보는 중복 등록할 수 없으며, 문구·아이콘만 다른 경우에는 기존 후보의 표시 정보 버전으로 관리한다.
• 기본 노출·추천 기준 (PI-DSP-QCK-003)
- 기본 퀵메뉴는 고객군과 무관하게 제공해야 하는 핵심 업무, 법정 고지, 장애 안내, 보안 필수 행동을 우선한다.
- 추천 퀵메뉴는 로그인 여부, 고객 상태, 보유 상품, 최근 행동, 진행 중 업무, 오퍼 대상 여부 같은 승인된 조건 안에서만 산정한다.
- 한 Container 안에서 노출 가능한 퀵메뉴 개수, 정렬 기준, 대체 후보, 빈 상태 처리를 사전에 정의해야 한다.
• 고객 고정·숨김 반영 (PI-DSP-QCK-004)
- 고객이 고정한 항목은 운영 추천 순위보다 우선하되, 실행 권한이 없거나 연결 대상이 미승인 상태이면 노출하지 않는다.
- 고객이 숨김 처리한 항목은 동일 Container에서 최소 30일 동안 재노출하지 않으며, 동일 주제의 다른 후보도 후순위로 낮춘다.
- 법정 고지, 장애 안내, 보안 필수 행동은 숨김 제한보다 우선할 수 있으나, 예외 사유와 적용 기간을 남겨야 한다.
• 실행 불가·대체 처리 (PI-DSP-QCK-005)
- 고객 상태나 권한 때문에 실행할 수 없는 바로가기는 노출 제외를 기본으로 하며, 운영자가 안내형 노출을 선택한 경우에만 비활성 상태로 노출한다.
- 비활성 노출 시 실행 불가 사유, 가능한 다음 행동, 대체 랜딩 또는 상담 연결값을 함께 등록해야 한다.
- CVM 또는 업무 시스템 응답 실패로 실행 가능 여부를 판단할 수 없으면 기본 퀵메뉴 또는 사전에 지정한 대체 후보를 제공한다.
• 변경 이력·성과 확인 (PI-DSP-QCK-006)
- 퀵메뉴 후보, 기본 노출 목록, 추천 조건, 고정·숨김 예외를 변경할 때는 변경 사유, 담당 조직, 적용 채널, 적용 시작일시, 롤백 대상을 저장한다.
- 퀵메뉴 성과는 노출수, 클릭수, 실행 성공, 실행 불가, 숨김, 재진입 지표로 확인하고 성과 이상 또는 오류가 있으면 중지하거나 이전 승인 버전으로 되돌린다.

6) 개인화 노출·숨김 정책 (PG-DSP-PER-001)

• 개인화 적용 조건 (PI-DSP-PER-001)
- 개인화 판단에 사용하는 고객 상태, 보유 상품, 최근 행동, 오퍼 대상 여부 등은 전시 어드민에서 직접 값을 입력하지 않고 CVM 등 승인된 연계 시스템의 판정값을 참조한다.
- 전시 어드민은 사용할 수 있는 조건 항목, 적용 대상 Component·Corner·Template, 노출·제외 기준, 우선순위, 대체 전시를 설정한다.
- 개인화 조건에는 조건명, 데이터 출처, 적용 근거, 제한 사유, 실패 시 처리 방식을 필수 등록한다.
- 개인화 조건은 여정 단계, 세그먼트, 고객 의도, 필요 정보, 관계 맥락 중 어떤 기준을 사용했는지 구분해 저장한다.
- 개인화 적용 수준은 공통 전시, 고객 특징 기반 전시, 고객 성향·행동 기반 전시로 구분하고, 각 수준별 대체 전시를 지정한다.
- CVM에서 제공되지 않거나 승인되지 않은 고객 속성은 운영자가 임의로 입력해 개인화 조건으로 사용할 수 없다.
• CVM 판정 실패 처리 (PI-DSP-PER-002)
- 전시 연계 시스템(CVM)이 필요한 데이터를 제공하지 못하거나 응답 지연·오류·필수 필드 누락이 발생하면 개인화 후보를 확정하지 않는다.
- 이 경우 고객에게는 기본 Template, 기본 전시 또는 사전에 지정한 대체 전시를 제공하고, 오퍼·추천·혜택 개인화 영역은 제외하거나 공통 전시로 대체한다.
- 실패 사유, 요청 조건, 응답 상태, 대체 전시 ID, 반영 시각을 판정 이력으로 저장한다.
• 숨김·관심없음 반영 (PI-DSP-PER-003)
- 숨김 또는 관심없음이 등록된 동일 캠페인·동일 소재는 최소 30일 동안 재노출하지 않는다.
- 동일 주제의 다른 후보는 후순위로 낮추고, 운영자는 제한 이력 해제 전 강제 노출할 수 없다.

7) 표준 Atom·컴포넌트·자산 정책 (PG-DSP-CMP-001)

• Atom 등록 기준 (PI-DSP-CMP-001)
- Atom은 텍스트, 버튼, 이미지, 아이콘, 배지, 가격, 혜택 문구, CTA, 정보값 중 하나의 유형으로 등록한다.
- Atom 등록 시 유형, 사용 목적, 허용 Component, 타겟 세그먼트, 배리에이션 수, 표기 제한, 디자인 라이브러리 에셋 연결값을 필수 입력한다.
!디자인 라이브러리 협의 필요Atom 유형, 허용 Component, 에셋 연결값, 표기 제한은 디자인 라이브러리에서 제공하는 토큰·컴포넌트 기준과 맞춰 확정해야 한다.- 이미지·아이콘 Atom은 대체텍스트와 허용 포맷·해상도 기준을 통과해야 검수 요청할 수 있다.
• Component 등록 기준 (PI-DSP-CMP-002)
- Component는 사전에 등록된 Atom 조합으로만 생성하며, 유형을 반드시 가진다.
- Component 유형 예시는 상품형, 정보형, 행동형, 혜택형, 선택형, 배너형이며, 실제 유형명과 속성은 상세 설계에서 확정한다.
- Component 등록 시 필수 Atom, 선택 Atom, 데이터 매핑 방식, 노출 조건, 빈 상태, 랜딩 연결값, 사용 가능 Corner 유형을 필수 정의한다.
- Component 노출 유형은 화면에 표시할 데이터 Set을 기준으로 관리한다.
- 상품형 Component는 대표 이미지, 상품명, 가격, 배지, CTA 같은 노출 데이터 Set을 가진다.
- Corner 유형별로 사용할 수 있는 Component 노출 유형과 노출 데이터 Set을 제한한다.
- Component 유형과 속성은 디자인 라이브러리와 Component Library 기준을 우선 사용하며, 신규 유형은 사용 목적과 허용 Corner 유형을 검수 후 등록한다.
- 상품 선택형 Component는 상품군, 선택 기준, 기본 선택값, 선택 후 CTA, 선택 불가 조건을 필수값으로 둔다.
• Corner 구성 기준 (PI-DSP-CMP-003)
- Corner에는 Corner명, 목적, Corner 유형, 최대 노출 개수, 정렬 기준, 포함 가능 Component 유형, 빈 상태 처리를 필수 등록한다.
- Corner 유형 예시는 상품형, 배너형, 혜택·오퍼형, 업무 진입형, 상태 안내형, 콘텐츠 안내형, 개인화 추천형, 고정·필수 노출형이며, 실제 유형명은 상세 설계에서 확정한다.
- Corner 유형과 Component 유형은 같은 분류 체계로 관리한다.
- Corner 유형을 선택하면 연결 가능한 Component 유형을 자동으로 제한한다.
- 상품형 Corner는 상품형 Component만 사용할 수 있고, 배너형 Corner는 배너형 Component만 사용할 수 있다.
- Corner 저장 시 Corner 정보와 Component 정보를 함께 저장한다.
- Corner 저장 필수값은 Corner명, Corner 유형, Component 유형, 노출 데이터 Set, 사용 여부다.
- Corner 유형별 허용 Component 유형에 포함되지 않은 Component는 등록을 차단한다.
- 예외 등록이 필요한 경우 예외 사유, 적용 기간, 영향 범위를 입력하고 승인받아야 한다.
- Corner의 최대 노출 개수보다 많은 Component 후보가 있으면 우선순위 정책에 따라 자동 제외하고 제외 사유를 저장한다.
• 자산 검증 기준 (PI-DSP-CMP-004)
- 이미지, 동영상, 아이콘, 배너 소재는 파일 포맷, 용량, 해상도, 사용 권한, 대체텍스트를 검증해야 한다.
- 이미지, 아이콘, 배너 소재 안에 고객이 알아야 할 문구, 혜택, 조건, 금액, 기간, 행동 안내가 포함된 경우에는 동일한 의미를 대체텍스트로 등록해야 한다.
- 대체텍스트가 필요한 소재에 대체텍스트가 없으면 검수 요청을 차단한다. 장식용 이미지는 대체텍스트를 비워둘 수 있으나, 고객에게 전달해야 할 정보가 없다는 제외 사유를 저장해야 한다.
- 동일 자산이 2개 이상 사용처에 연결된 경우 교체·삭제 전 영향 범위를 먼저 확인하게 한다.

8) 배너 캠페인·일괄 제어 정책 (PG-DSP-BNR-001)

• 캠페인 필수값 (PI-DSP-BNR-001)
- 배너 캠페인은 자동 생성되는 캠페인 ID, 캠페인명, 목적, 담당 조직, 운영 채널, 전시 여부, 시작일시, 종료일시, 배너 유형, 소재, 랜딩 연결값, 노출 조건, 사용처를 필수 등록한다.
- 종료일시가 없는 상시 캠페인은 상시 운영 여부를 별도로 선택하고, 운영 종료 또는 교체 기준을 함께 등록한다.
- 기간, 소재, 랜딩, 운영 채널, 전시 여부 중 하나라도 비어 있으면 검수 요청을 차단한다.
• 사용처·영향 범위 (PI-DSP-BNR-002)
- 동일 캠페인은 여러 Container, Template, Corner, 상품 상세 공통 영역에 배치할 수 있다.
- 사용처별 노출 위치, 기간, 게시 상태, 소재 버전, 대체 소재를 조회한다.
- 일괄 중지, 기간 변경, 소재 교체는 사용처 영향 범위를 확인하고 승인된 뒤에만 적용한다.
- 캠페인이 중지되거나 종료되면 연결된 모든 사용처의 배너 노출도 함께 종료한다.
• 배너형 Component 판정 (PI-DSP-BNR-003)
- 화면 안의 배너는 배너형 Component로 배치한다.
- 서비스 전체 캠페인은 배너 관리 메뉴에서 캠페인 단위로 관리한다.
- 동일 소재라도 규격, 랜딩, 노출 조건이 다르면 별도 배너 유형 또는 소재 버전으로 관리한다.
- 동일 캠페인도 사용처별로 다른 소재 버전을 가질 수 있다.
- 이미지, 문구, 배경색, 대체텍스트, CTA, 대상 상품 매핑은 사용처별 규격에 맞게 검증한다.
• CVM 타겟 배너 수신 기준 (PI-DSP-BNR-004)
- CVM이 타겟 배너를 전달하면 전시 어드민은 구좌 ID, 캠페인 ID, 소재, 문구, 랜딩, 노출 조건, 기간, 우선순위를 확인한다.
- CVM 수신 배너도 랜딩, 대체텍스트, 노출 조건, 사용처 영향 범위 검증을 통과해야 게시할 수 있다.
- 소재가 만료, 누락, 접근 불가, 규격 불일치 상태이면 노출하지 않는다.
- 노출하지 못하는 경우 기본 배너 또는 사전 지정한 대체 배너로 전환한다.
- 수신 시각, 판정 조건, 소재 버전, 게시 여부, 대체 사유는 전시 이력으로 저장한다.
!CVM 전달방식 협의 필요CVM이 배너 구좌와 소재를 함께 전달하는 경우 구좌 ID, 소재 전달 방식, 이미지 호스팅 책임, 캐시·만료 처리, 대체 배너 기준을 확정해야 한다.
• 캠페인 조회·운영 상태 기준 (PI-DSP-BNR-005)
- 배너 관리 목록은 캠페인 ID, 캠페인명, 운영 채널, 전시 여부, 승인 상태, 전시기간, 등록자, 최종 수정자, 등록일시, 최종 변경일시를 조회 조건과 결과 항목으로 제공한다.
- 캠페인은 임시저장, 승인요청, 승인완료, 반려의 승인 상태와 진행예정, 진행중, 일시중단, 기간종료의 운영 상태를 구분해 관리한다.
- 생성된 캠페인은 이력 보존을 위해 삭제하지 않고 미전시 또는 일시중단 상태로 전환한다.
• 수정·재승인 기준 (PI-DSP-BNR-006)
- 승인 완료된 캠페인의 소재, 랜딩, 기간, 노출 조건, 사용처를 수정하면 재승인을 요청해야 한다.
- 진행 중인 캠페인을 수정해 재승인을 기다리는 동안에는 기존 승인 버전을 계속 노출하고, 수정본은 승인 완료 후 교체 반영한다.
- 변경 이력에는 변경 항목, 이전값, 이후값, 변경 사유, 수정자, 승인 상태, 반영 시각을 저장한다.
• 배너 관리·Corner 배치 역할 구분 (PI-DSP-BNR-007)
- 배너 관리 메뉴에서는 캠페인 기본 정보, 소재 버전, 랜딩, 기간, 전시 여부와 복수 사용처를 관리한다.
- Container 관리의 배너형 Corner에서는 캠페인 후보의 포함·제외, 노출 순서, 최대 노출 개수, 로그인 여부 등 위치별 노출 기준을 관리한다.
- 어느 화면에서 캠페인을 추가·제외하더라도 배너 관리와 Corner 배치 정보는 동일 사용처 이력으로 연동하며, 수동 순서 지정형 Corner에는 신규 캠페인의 초기 순서를 운영자가 확인하도록 한다.

9) 랜딩 연결 검증 정책 (PG-DSP-LNK-001)

• 랜딩 필수값 (PI-DSP-LNK-001)
- CTA 또는 배너 소재에는 랜딩 유형, 연결값, 채널, 로그인 필요 여부, 권한 조건, 추적 파라미터를 필수 등록한다.
- 랜딩 유형은 내부 화면, 외부 URL, 상담 연결, 앱 딥링크, 다운로드, 없음 중 하나로 선택한다.
- 외부 접점에서 유입되는 딥링크와 내부 화면에서 외부 접점으로 이동하는 랜딩은 유입 경로, 복귀 경로, 권한 조건, 추적 파라미터를 함께 검증한다.
• 연결값 차단 기준 (PI-DSP-LNK-002)
- 만료 URL, 승인되지 않은 외부 도메인, 권한 없는 내부 화면, 필수 파라미터 누락, 4xx·5xx 응답 링크는 게시 전 차단한다.
- 차단 시 오류 유형, 확인 시각, 수정 담당자를 링크 검증 이력으로 저장한다.
• 랜딩 변경 기준 (PI-DSP-LNK-003)
- 운영 중 랜딩을 변경하면 기존 캠페인 파라미터와 성과 추적값 유지 여부를 검증한다.
- 랜딩 목적이 바뀌는 변경은 단순 수정이 아니라 재검수 대상으로 처리한다.

10) 노출 조건·우선순위·충돌 정책 (PG-DSP-RUL-001)

• 조건 필수값 (PI-DSP-RUL-001)
- 노출 조건에는 조건명, 조건 유형, 판정 데이터 출처, 포함·제외 기준, 우선순위, 실패 시 처리 방식을 필수 등록한다.
- 판정 데이터 출처가 CVM인 조건은 응답 실패, 지연, 필수값 누락 시 적용할 기본 Template 또는 대체 전시를 사전에 지정해야 한다.
- 조건 유형은 로그인, 채널, OS, 앱 버전, 보유 상품, 전시 대상 상태, 멤버십 등급, 세그먼트, 오퍼 대상, 여정 단계, 고객 의도, 권한, 기간, 빈도 중 하나 이상으로 구분한다.
• 전시 가능 여부 판정 (PI-DSP-RUL-002)
- 전시 대상의 전시 가능 여부는 BSS 또는 전시 연계 시스템(CVM)에서 제공받은 상태 정보를 사용해 판정한다.
- 전시 어드민은 휴대폰, 요금제, 구독, 혜택처럼 대상 유형별 세부 판매·이용 정책을 재정의하지 않고, 전시에 사용할 수 있는 대상인지 여부만 판정한다.
- 전시 가능으로 확인된 대상은 승인 상태, 게시 기간, 채널, 세그먼트, 우선순위 조건을 추가로 검증한다.
- 전시 불가로 확인된 대상은 추천·배너·선택형 Component 후보에서 제외한다.
- 전시 가능 여부를 확인할 수 없으면 기본 전시 또는 대체 전시로 전환하고, 판정 실패 이력을 저장한다.

Y전시 예정예약 또는 대기시작일시 또는 제공 가능 시점 전에는 노출하지 않고, 기본 전시 또는 대체 전시를 적용한다.

• Corner 유형 변경 처리 (PI-DSP-RUL-002-1)
- Corner 유형 변경은 기존 Corner·Component 정보의 유지 여부를 함께 판단한다.
- 같은 Component 대분류 안에서 유형을 변경하면 기존 Corner 정보와 Component 정보를 유지한다.
- 다른 Component 대분류로 변경하면 기존 Corner 정보와 Component 정보를 초기화한다.
- 예를 들어 상품형 안에서 가로형을 세로형으로 바꾸는 경우에는 정보를 유지하고, 상품형을 배너형으로 바꾸는 경우에는 기존 정보를 초기화한다.
- 초기화가 필요한 변경은 영향 범위 확인과 재검수 후에만 반영한다.
• 충돌 판정 기준 (PI-DSP-RUL-003)
- 동일 Slot 또는 동일 Corner 최대 노출 개수를 초과하는 후보가 있으면 필수 고지, 승인 우선순위, 종료 임박, 캠페인 우선순위, 최근 변경 시각 순으로 1차 판정한다.
- 포함 조건과 제외 조건이 동시에 참이면 제외 조건을 우선 적용한다.
• 빈도·기간 제한 (PI-DSP-RUL-004)
- 기간형 전시는 시작일시와 종료일시를 필수로 입력하며 종료일시가 없는 캠페인성 전시는 게시할 수 없다.
- 동일 고객 대상 반복 노출 제한은 캠페인 또는 Corner 단위로 설정하고, 설정값이 없으면 기본 노출 빈도 정책을 적용한다.
• 중복 요청 처리 (PI-DSP-RUL-005)
- 동일 전시 버전, 동일 Slot, 동일 조건으로 5분 안에 반복 게시·중지·캐시 무효화 요청이 들어오면 첫 요청 결과를 재사용한다.
- 중복 요청은 추가 노출, 추가 승인, 중복 이력을 만들지 않는다.

11) 검수·승인·게시 정책 (PG-DSP-WFL-001)

• 검수 요청 조건 (PI-DSP-WFL-001)
- 검수 요청은 필수값, 랜딩 연결값, 자산 규격, 노출 조건, 충돌 검증, 미리보기, 영향 범위 확인을 모두 통과한 경우에만 가능하다.
- P1 오류가 1건이라도 있으면 Review 상태로 전환할 수 없다.
• 승인 권한 (PI-DSP-WFL-002)
- 승인자는 전시 어드민에서 승인하며, 승인 완료 전에는 채널 반영, 예약 게시, 캐시 갱신 요청을 모두 차단한다.
- 미승인 상태에서는 기존 승인 버전 또는 기본 Template을 유지하고, 신규 등록·수정한 전시는 채널 노출 후보에서 제외한다.
- 채널별 예외가 포함된 건은 해당 채널 권한자의 확인 이력을 추가로 요구한다.
• 게시 전 판정 (PI-DSP-WFL-003)
- 게시 전에는 승인 상태, 게시 기간, 채널 반영 대상, 상품 판매 상태, 혜택 이용 가능 기간, 캐시 무효화 대상, 대체 전시, 롤백 버전을 확인한다.
- Template 변경 건은 승인 완료 시점에 동일 Container, 동일 조건 그룹, 동일 기간의 중복 여부를 다시 확인한다.
- 기본 Template 변경 건은 새 기본 Template 승인 완료 시점부터 적용하며, 기존 기본 Template의 종료 처리 여부를 함께 확인한다.
- 미승인, 기간 만료, 필수 데이터 미회신, 판매종료 상품, 이용 기간이 지난 혜택, 랜딩 오류, 소재 만료 중 하나라도 있으면 게시를 차단한다.
• 미리보기 기준 (PI-DSP-WFL-004)
- 검수자는 적용 채널, 로그인 여부, 대표 세그먼트, 주요 조건 그룹, 게시 기간 기준으로 미리보기를 확인해야 한다.
- 조건형 Template은 조건 충족과 조건 미충족 미리보기를 모두 확인해야 승인할 수 있다.

12) 긴급 중지·롤백 정책 (PG-DSP-RBK-001)

• 긴급 중지 조건 (PI-DSP-RBK-001)
- 오노출, 만료 소재 노출, 잘못된 랜딩, 심의·법무 이슈, 고객 피해 가능성, 핵심 업무 진입 장애가 확인되면 긴급 중지를 허용한다.
- 긴급 중지 시 중지 사유, 대상 Container·Campaign·Slot, 실행자, 실행 시각을 필수 저장한다.
• 롤백 허용 버전 (PI-DSP-RBK-002)
- 롤백은 승인 완료 이력이 있는 이전 버전 또는 기본 전시 버전으로만 허용한다.
- Draft, Review, Rejected 상태의 버전으로 롤백할 수 없다.
• 대체 전시 적용 (PI-DSP-RBK-003)
- 긴급 중지 대상 Slot에 대체 전시가 등록되어 있으면 대체 전시로 전환한다.
- Template을 중지하거나 회수한 뒤 조건에 맞는 Template이 없으면 기본 Template을 적용한다.
- 기본 Template도 사용할 수 없으면 빈 상태 정책 또는 기본 안내를 적용하고, 화면을 미설정 상태로 방치하지 않는다.
- 기본 Template으로 전환한 경우 전환 사유, 기존 Template, 적용 시각, 복구 대상을 이력으로 남긴다.

13) AI 운영 보조 정책 (PG-DSP-AI-001)

• AI 후보 생성 조건 (PI-DSP-AI-001)
- AI 후보 생성은 운영자가 목적, 대상 세그먼트, 배리에이션 수, 사용 가능 Atom·Component, 소재 조건을 입력한 경우에만 수행한다.
- AI는 문구, 이미지 조합, 배치, CTA, 후보 순서를 제안할 수 있으나 신규 게시 또는 승인 처리를 수행하지 않는다.
- Proactive AI Layer처럼 고객 맥락에 따라 선제 제안하는 영역도 전시 어드민에서는 AI 후보로 관리하며, 운영자 검수와 승인 전에는 채널에 노출하지 않는다.
• 운영자 확정 기준 (PI-DSP-AI-002)
- AI 후보는 운영자가 삭제, 편집, 추가, 선택한 뒤 확정한 항목만 검수 요청 대상이 된다.
- 확정 전 후보는 채널 반영, 예약 게시, 성과 집계 대상에서 제외한다.
• AI 검증 차단 기준 (PI-DSP-AI-003)
- 금칙어, 브랜드 금지 표현, 법무 필수 문구 누락, 저작권 불명확 소재, 대체텍스트 누락, 랜딩 불일치가 있으면 AI 후보를 검수 요청할 수 없다.
- AI 후보에는 생성 근거와 사용한 입력 조건을 함께 저장한다.
- AI 후보의 유용성은 노출수, 클릭, 실행 성공, 숨김, 관심없음, 후속 행동 지표로 검증하고, 성과가 낮거나 고객 불편 신호가 있으면 후보 사용을 중지한다.

14) 실험·가드레일 정책 (PG-DSP-ABT-001)

• 실험 등록 기준 (PI-DSP-ABT-001)
- A/B 실험은 가설, 대상 조건, 실험군·대조군, 표본 비율, 기간, KPI, 가드레일 지표, 중지 조건, 전체 적용 기준을 필수 등록한다.
- KPI, 가드레일 지표, 중지 조건, 대체 전시가 없는 실험은 게시할 수 없다.
- 실험 대상 전시는 승인 완료 상태의 Container, Template, Corner, Component, 배너 캠페인 중 하나여야 하며 Draft 또는 Review 상태의 항목은 실험 대상으로 사용할 수 없다.
• 실험 대상·표본 기준 (PI-DSP-ABT-002)
- 실험군과 대조군은 동일 고객이 동시에 둘 이상에 포함되지 않도록 분리해야 하며, 실험 기간 중 고객군 배정 기준을 변경할 수 없다.
- 로그인 여부, 채널, OS, 앱 버전, 고객군, 보유 상품 조건처럼 결과에 영향을 줄 수 있는 조건은 실험 등록 시 고정하거나 분석 차원으로 저장해야 한다.
- 표본 비율을 변경하려면 변경 사유와 적용 시각을 남기고, 변경 전후 결과를 분리해 집계한다.
• 동시 실험 충돌 제한 (PI-DSP-ABT-003)
- 동일 고객군, 동일 Container, 동일 Slot 또는 동일 랜딩에서 둘 이상의 실험이 동시에 진행되는 경우 실험 간 영향 여부를 검증해야 한다.
- 동일 지표에 영향을 주는 실험이 중복되면 우선순위를 지정하거나 하나의 실험만 게시한다.
- 충돌 가능성이 있는 실험을 병행하려면 영향 범위, 분리 기준, 결과 해석 방법을 사전에 등록해야 한다.
• 중지 판정 (PI-DSP-ABT-004)
- 랜딩 오류, 핵심 CTA 실패, CS 증가, 이탈률 급증, 법무·심의 이슈, 고객 피해 가능성이 발생하면 실험을 중지한다.
- 중지 기준은 수치 또는 명확한 이벤트 조건으로 등록하고, 임계치에 도달하면 자동 알림과 중지 검토 상태로 전환한다.
- 중지된 실험은 실험군 노출을 중단하고 기본 전시 또는 사전 지정한 대체 전시로 전환한다.
• 결과 판정 기준 (PI-DSP-ABT-005)
- 실험 결과는 등록된 KPI와 가드레일 지표를 함께 충족해야 성공으로 판정할 수 있다.
- 조기 종료 결과, 단일 클릭률 상승, 특정 채널·고객군에 한정된 상승만으로 전체 적용을 승인하지 않는다.
- 결과 판정 시 노출수, 클릭수, CTR(클릭률), 후속 행동, 전환, 숨김·관심없음, 이탈, 오류 지표를 함께 확인한다.
• 전체 적용·종료 이력 (PI-DSP-ABT-006)
- 전체 적용은 검수·승인 완료 후 신규 전시 버전, 기간형 Template, 배너 소재 교체, 조건 조정 중 하나로 반영한다.
- 실험 종료 시 가설, 대상 조건, 기간, 표본 비율, 결과 지표, 판정 사유, 적용 여부, 롤백 대상을 실험 이력으로 저장한다.
- 실패 또는 중단된 실험의 후보는 동일 조건으로 즉시 재게시할 수 없으며, 원인 보완 후 새 실험으로 등록한다.

15) 성과 측정·개선 정책 (PG-DSP-MET-001)

• 성과 판정 지표 (PI-DSP-MET-001)
- 전시 성과는 노출수, 클릭수, CTR(클릭률), 랜딩 도달, 후속 행동, 전환, 숨김, 관심없음, 오류 중 최소 2개 이상 지표로 판정한다.
- 클릭률만으로 성공 또는 개선 여부를 확정하지 않는다.
• 피로도 판정 (PI-DSP-MET-002)
- 동일 주제 반복 노출, 숨김 증가, 관심없음 증가, 이탈률 증가 중 2개 이상이 동시에 발생하면 피로도 위험으로 판정한다.
- 피로도 위험 전시는 빈도 제한, 후순위 조정, 소재 교체, 중지 중 하나의 조치를 선택한다.
• 개선 반영 기준 (PI-DSP-MET-003)
- 성과 개선안은 신규 버전, 기간형 Template, 배너 소재 교체, 조건 조정, 실험 등록 중 하나로 반영한다.
- 개선 반영 전에는 대상, 사유, 기대 효과, 롤백 기준을 필수 등록한다.

16) 권한·감사 이력 정책 (PG-DSP-AUD-001)

• 권한 분리 (PI-DSP-AUD-001)
- 작성, 검수, 승인, 게시, 긴급 중지, 롤백 권한은 역할별로 분리한다.
- 담당 조직과 사업 영역을 기준으로 Container, Template, Corner, Component, Campaign의 조회·작성·수정·승인 범위를 제한한다.
• 감사 로그 필수값 (PI-DSP-AUD-002)
- 변경 이력에는 변경자, 변경일시, 변경 대상, 이전값, 이후값, 변경 사유, 승인자, 게시 결과를 저장한다.
- Container, Template, Corner, Component, Atom, 캠페인, 랜딩, 조건, 상태 변경은 모두 감사 로그 대상이다.
• 보관 기준 (PI-DSP-AUD-003)
- 운영 변경, 승인, 게시, 롤백, 긴급 중지, 개인화 제한 이력은 최소 1년 보관한다.
- 고객 식별이 가능한 로그는 대체키 또는 마스킹값으로 저장하고, 보관 기간 만료 후 원천 로그를 파기한다.

17) 표기 검증 정책 (PG-DSP-ACC-001)

• 가격·혜택 표기 필수값 (PI-DSP-ACC-001)
- 가격, 할인, 포인트, 쿠폰, 결합 혜택은 적용 기간, 대상, 제외 조건, 예상·확정 여부를 함께 등록한다.
- 조건이 긴 경우 상세 안내로 연결하되 핵심 제한 조건은 전시 본문 또는 대체텍스트에 남긴다.
• 메시지 판정 기준 (PI-DSP-ACC-002)
- 한 소재의 핵심 메시지는 1개로 제한하고 보조 문구는 2개 이하로 둔다.
- CTA 문구는 고객 행동을 명시해야 하며, 랜딩 목적과 다르면 검수 요청을 차단한다.
• 이미지 대체 정보 (PI-DSP-ACC-003)
- 이미지, 아이콘, 배너 소재에는 대체텍스트를 필수 등록한다.
- 대체텍스트에는 이미지 안의 핵심 메시지, 혜택, 가격, 기간, CTA 의미를 문장으로 포함하고, 파일명이나 “이미지” 같은 무의미한 문구만 입력할 수 없다.
- 장식용 이미지로 등록하는 경우 대체텍스트 제외 사유를 저장하고, 정보 전달 내용이 없을 때만 허용한다.

최종 점검 기준

전시 어드민 정책서 제출 전 점검
1. 관리 범위
Container, Template, Corner, Component, Atom, 배너 캠페인, 랜딩, 노출 조건, 게시 상태를 전시 어드민 관리 대상으로 정의한다.
주문, 가입, 납부, 상담 같은 후속 업무 처리 로직은 전시 정책 범위에서 제외한다.
2. 필수값
저장 가능 조건과 검수 요청 가능 조건을 구분한다.
필수값 누락 시 저장 허용, 검수 차단, 게시 차단 중 어떤 판정을 적용할지 명시한다.
Container별 기본 Template과 조건 그룹별 기본 Template 지정 여부를 확인한다.
3. 조건 판정
조건 속성 N/Y, 조건 그룹, 폴백 Template, 조건 미충족 처리 기준을 정의한다.
로그인/비로그인 등 같은 조건 그룹 안에서는 전시 중 또는 전시 예정 Template 중복을 허용하지 않는다.
BSS와 CVM에서 받은 원천 조건의 확인 기준을 둔다.
조건 충돌 시 포함 조건, 제외 조건, 동일 Slot 경쟁 후보의 판정 순서를 정의한다.
4. 승인·게시
승인 권한, 승인 전 예약·게시 차단, 게시 전 자동 검증, 채널별 반영 결과 회신 기준을 포함한다.
미승인 상태에서는 기존 승인 전시 또는 기본 Template을 유지한다.
기본 Template 교체 시 기존 기본 Template의 종료 처리 기준을 둔다.
5. 배너·소재
배너 캠페인은 기간, 소재, 랜딩, 사용처, 노출 조건, 일괄 제어 영향 범위를 필수로 가진다.
소재 교체, 기간 변경, 일괄 중지는 사용처 확인과 승인 후에만 허용한다.
6. AI 보조
AI는 후보 생성과 근거 제안까지만 수행한다.
운영자 확정·검수·승인 전에는 게시하지 않는다.
AI 후보의 입력 조건, 생성 근거, 삭제·편집·추가 이력을 남긴다.
7. 롤백·중지
긴급 중지 조건, 롤백 허용 버전, 대체 전시 적용 기준을 정의한다.
Draft, Review, Rejected 상태의 버전으로 롤백할 수 없다.
중지·회수 후 적용 가능한 Template이 없으면 기본 Template 또는 빈 상태 정책으로 전환한다.
8. 이력·권한
변경자, 변경일시, 변경 대상, 이전값, 이후값, 변경 사유, 승인자, 게시 결과를 감사 로그로 남긴다.
담당 조직과 사업 영역 기준으로 조회·작성·수정·승인 권한을 분리한다.
9. 정책 구체성
정책 항목은 필수값, 차단 조건, 허용 조건, 우선순위, 기간, 횟수, 이력, 보관 기준 중 하나 이상을 포함한다.
“등록 기준”, “관리 기준”처럼 이름만 있는 항목은 상세 기준으로 보완한다.
10. 추적성
유즈케이스, 프로세스, 기능, 정책 ID를 서로 연결한다.
정책 상세의 판정 기준은 스토리보드 화면 항목 또는 개발 검증 조건으로 전환할 수 있게 작성한다.
